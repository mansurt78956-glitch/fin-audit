# Устройство Bookrift и результаты проверки

## Бухгалтерская модель

Эпизод описывает одну вымышленную компанию и её январский отчётный период. В книгах есть операции соседних периодов, иностранные счета, частичные платежи, разбивка платежей и возвраты. Два счёта могут иметь одинаковую сумму. Дубль подтверждается повтором номера счёта поставщика и двойным отражением обязательства.

Погашение фиксируется в базовой валюте по курсу на местную дату счёта. Суммы хранятся целыми в минимальных единицах, курс — десятичной строкой в направлении `target_major_per_source_major`. Округление выполняется по `ROUND_HALF_UP`. Время записывается со смещением. Отсутствующая связь в CSV обозначается значением `csv_null` из манифеста, а в API возвращается JSON `null`.

`partial_fx` соединяет ошибку курса с неполным или пропущенным распределением платежа. `cutoff_fx` меняет сумму и период одной пары проводок. Ошибка периода считается по правильной стоимости счёта, поэтому обе суммы можно проверить отдельно. Публичный файл `policy.json` описывает затронутые ID, доказательства и расчёт суммы для каждого типа ошибки.

## Эталон и награда

В `provenance.json` запись `base_book` содержит контрольную сумму и размеры исходных регистров. Каждая запись `mutation` связывает `issue_id` со списком изменений. В изменении указаны таблица, `before` и `after`. Для добавленной записи `before` равен `null`. Обратное применение изменений восстанавливает исходные книги. Этот процесс и доказательства проверяет [test_dataset.py](fin_audit_rl/tests/test_dataset.py).

Matcher сравнивает тип, множество затронутых ID, валюту и сумму. Все переданные доказательства должны быть доступны, а их множество должно включать один полный набор из эталона. По умолчанию денежный допуск равен нулю. Фикстура может задать его целым числом в `policy.amount_tolerance_minor`. Каждый вывод сопоставляется максимум с одной ошибкой. Среди максимальных паросочетаний выбирается лексикографически первое по `issue_id` и индексу вывода.

Награда рассчитывается как `clip(2 * F1 - 1 - 0.002 * inspection_steps, -1, 1)`. Каждый запрос до `submit`, включая ошибочный, считается исследовательским шагом. Пустой ответ при пустом эталоне даёт F1 = 1. При невалидной отправке награда равна −1. В закрытом режиме эти значения доступны только оценщику.

## Локальные результаты

Четыре политики проверяются на одних и тех же 20 эпизодах. В наборе пять чистых эпизодов, пять с взаимодействиями и десять с другими наборами ошибок. В таблице указаны средние значения. У чистого эпизода с пустым ответом точность и полнота равны нулю по соглашению о нулевом знаменателе.

| Политика | Точность | Полнота | F1 | Награда | Шаги |
| --- | ---: | ---: | ---: | ---: | ---: |
| Случайное исследование | 0,00 | 0,00 | 0,25 | −0,5020 | 5,00 |
| Программная сверка | 0,75 | 0,75 | 1,00 | 0,9482 | 26,90 |
| Массовая пометка | 0,00 | 0,00 | 0,00 | −1,0000 | 2,00 |
| Oracle | 0,75 | 0,75 | 1,00 | 1,0000 | 1,00 |

Программная сверка нашла 45 ошибок без ложных срабатываний. Случайная политика пропустила все 45. Массовая пометка пропустила их и сделала 600 ложных выводов. Результаты каждого прогона сохранены в [baseline_results.json](artifacts/baseline_results.json).

Проверка matcher воспроизводит случай, в котором к полному набору доказательств добавлен несуществующий ID. Вывод должен стать FP. Тесты адаптера также загружают с диска исходный и преобразованный эпизоды, сравнивают метрики и проверяют, что награда закрытого прогона недоступна агенту. [test_judge_adapter.py](fin_audit_rl/tests/test_judge_adapter.py)

## Ограничения

Политика сверки использует правила этой синтетической бухгалтерии. Показатели относятся к локальному набору и не измеряют качество обучения модели. Локально проверены Python 3.12 и параметры запуска контейнера. Полный прогон на Python 3.11 внутри Docker требует работающего Docker Engine.
