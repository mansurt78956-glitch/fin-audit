# Среда финансового аудита для обучения с подкреплением

Детерминированная офлайн-среда для обучения и оценки политик финансового аудита на синтетических книгах. Политика запрашивает записи, сверяет документы и отправляет выводы с доказательствами.

## Быстрый запуск

Откройте терминал в корне проекта, где находятся `README.md` и папка `fin_audit_rl`. Целевая версия — Python 3.11. Среда использует стандартную библиотеку. Убедитесь, что команда `python --version` показывает нужный интерпретатор.

```powershell
python -m fin_audit_rl.cli --check --out artifacts
python -m fin_audit_rl.cli --out artifacts
```

Первая команда запускает 33 теста и оценивает четыре базовые политики на одних и тех же 20 эпизодах локальной проверки. После успешного завершения она записывает `artifacts/baseline_results.json`. Вторая обновляет этот отчёт, 10 открытых обучающих эпизодов (`train`), 10 проверочных эпизодов (`dev`) и файл `artifacts/trajectories.jsonl`. Повторный запуск обновляет сгенерированные файлы в выбранном каталоге. Описание проверок по критериям задания и результаты приведены в [DESIGN.md](DESIGN.md).

Демо показывает первое действие сверки, две найденные ошибки и оценку вывода.

```powershell
python -m fin_audit_rl.cli --demo
```

Проверка использует стандартную библиотеку без сети, GPU и платных API. Для контейнерных команд установите и запустите Docker с поддержкой Linux-контейнеров. Пока сеть доступна, подготовьте образ и соберите проект.

```powershell
docker info
docker pull python:3.11-slim
docker build --network none -t fin-audit-rl .
```

Готовый образ позволяет выполнить проверку с отключённой сетью контейнера. Команда выполняет тесты и локальные базовые политики, а результат проверки выводится в терминал. Файлы отчёта сохраняются внутри временного контейнера.

```powershell
docker run --rm --network none --cpus 2 --memory 4g fin-audit-rl python -m fin_audit_rl.cli --check
```

Проверка изоляции отдельного агента запускается на компьютере с доступным Docker и заранее подготовленным образом `python:3.11-slim`.

```powershell
python -m fin_audit_rl.docker_smoke
```

Проверка запускает минимального агента из `examples/docker_agent` в контейнере и оценивает его на чистом эпизоде. Для официального запуска нужна работающая служба Docker. Образ следует скачать заранее для последующей автономной оценки. Другой локальный образ можно указать параметром `--image ИМЯ_ОБРАЗА`.

## API среды

```python
from fin_audit_rl import AuditEnv

env = AuditEnv(mode="train")  # В режиме eval награда и метрики доступны оценщику.
observation, info = env.reset(seed=42, config={"transactions": 50, "issue_types": ["period_cutoff"]})
observation, reward, terminated, truncated, info = env.step(
    {"action": "list_records", "table": "ledger", "cursor": None, "limit": 50}
)
```

Поддерживаются `list_records`, `get_record`, `get_document`, арифметический `calculator` и `submit`. Страница ограничена 50 записями, а курсор передаётся как целое число или `null`. `get_document` ищет `doc_id` в счетах и платежах. У строки FX есть `rate_id`. Максимум 100 действий, включая отправку. Ошибочные запросы расходуют шаг. Исследовательские шаги имеют нулевую награду. Исчерпание времени или шагов даёт `truncated=true` и оценивается как пустой итоговый ответ. В `eval` баллы и диагностика доступны только оценщику. ID эпизода непрозрачный, а seed используется только при сбросе на стороне оценщика.

`submit` принимает `episode_id` и список `findings` из максимум 30 элементов. Каждый элемент содержит `type`, `affected_ids`, целый `claimed_amount_minor`, `currency`, до 10 `evidence_ids` и строку `explanation` длиной до 1 000 символов.

### Изоляция агента при закрытой оценке

Для запуска внешних политик используйте `run_isolated_episode` из `fin_audit_rl.runner`. Объект `AuditEnv`, эталон и код сопоставления находятся в основном процессе оценщика. Агент выполняется в отдельном процессе и обменивается построчными JSON-сообщениями через стандартные потоки ввода и вывода. В режиме `eval` итоговая награда и метрики доступны оценщику.

```python
from fin_audit_rl import AuditEnv
from fin_audit_rl.runner import run_isolated_episode

result = run_isolated_episode(
    AuditEnv(mode="eval"),
    ["python", "-u", "agent.py"],
    seed=42,
    config={"transactions": 40, "issue_count": 0},
    backend="docker",
    image="python:3.11-slim",
    solution_dir="examples/docker_agent",
)

print(result["status"], result["evaluator_metrics"])
```

Режим `backend="docker"` использует локальный образ, отключает сеть, монтирует каталог решения для чтения, убирает дополнительные полномочия Linux, запрещает повышение привилегий и ограничивает память, число ядер процессора и число процессов. В `solution_dir` передавайте отдельный каталог с файлами агента. Служба Docker и основной процесс оценщика входят в доверенную часть системы. Режим `backend="local"` предназначен для разработки и использует права текущего пользователя. Оценщик отправляет исходное наблюдение после сброса, затем после каждого действия возвращает наблюдение и признаки завершения. Ответ агента состоит из одной JSON-строки `{"action": {...}}`. Стандартный вывод `stdout` используется для протокола.

## Данные, генератор и приватность

`generate_episode(seed, config)` сначала строит сбалансированные книги, затем вносит ошибки и сохраняет их обратимые изменения в истории генерации (`provenance`). Поддерживаются `duplicate_invoice`, `payment_allocation`, `fx_date_rate` и `period_cutoff`. Чистые книги содержат корректные частичные и разбитые платежи, возвраты и повторяющиеся суммы. `partial_fx` объединяет ошибку конвертации иностранного счёта и неполное или отсутствующее распределение его платежа в базовой валюте. `cutoff_fx` меняет период и базовую сумму одной пары проводок.

Описание эпизода (`manifest`) фиксирует версии схемы и генератора, границы периода, часовой пояс, размеры регистров, валютную разрядность и округление. Время хранится в ISO-8601 со смещением, суммы — в целых минимальных денежных единицах, котировки — в десятичных строках. В CSV отсутствующие ссылки записываются как `null` согласно полю `manifest.csv_null`. API возвращает JSON `null`. Правила компании включают котировку на местную дату счёта и фиксированное погашение по договорной сумме в базовой валюте. Регистры содержат соседние даты для проверки границ периода и сверки входящих остатков. По умолчанию создаётся 64 счёта. Настройки `transactions` (20–400), `base_currency` (USD, EUR, GBP, KZT, JPY), `timezone`, `issue_count` (0–12), `issue_types` или `interaction_scenario` задают размер и состав эпизода.

Открытые наборы и локальные проверки используют встроенные часовые пояса. Для других имён IANA требуется доступная локальная база часовых поясов. Поле `policy.reporting` содержит список требуемых идентификаторов, доказательств и правила расчёта суммы для каждого типа вывода.

Интерфейс командной строки сохраняет публичные записи и версионированные `episodes.json` в `artifacts/open/{train,dev}`. В `artifacts/evaluator/{train,dev}` хранятся эталон и история генерации. Закрытые прогоны используют этот же интерфейс с начальными значениями генератора (`seed`) и настройками, которые задаёт организатор. Начальные значения локального диагностического набора опубликованы для воспроизведения результатов.

## Оценивание

`matcher.py` реализует взаимно-однозначное сопоставление по типу, ID, валюте, сумме с допуском 0 и полному разрешённому набору доказательств. Максимальное паросочетание разрешает неоднозначные совпадения с устойчивой сортировкой кандидатов по разнице суммы и индексу эталона. Повтор вывода с изменённым списком доказательств даёт одно место в сопоставлении. Остальные повторные и несопоставленные выводы учитываются как FP. Терминальная награда вычисляется по формуле задания.

`clip(2 * F1 - 1 - 0.002 * inspection_steps, -1, 1)`

Пустой эталон и пустая отправка дают F1=1. Ложные выводы на чистом эпизоде дают F1=0. Текст `explanation` служит для обоснования вывода. Невалидная отправка завершается с -1. Открытый режим возвращает метрики в `info`, закрытый сохраняет их на стороне оценщика.

Четыре базовые политики включают случайного исследователя, программную сверку открытых записей, массовую пометку строк и эталонную политику оценщика (`oracle`). Файл `baseline_results.json` содержит точность P, полноту R, F1, возврат, шаги и время для каждой политики на 20 локальных эпизодах. Файл `trajectories.jsonl` содержит по одному прогону случайного исследователя и программной сверки на каждом из 10 обучающих эпизодов. Группируйте строки по `trajectory_id`. Строка с `step=0` содержит исходное наблюдение и `action=null`, последующие строки описывают переходы и награды.

## Сгенерированные материалы

Команда генерации создаёт в `artifacts/open/train` обучающий набор, а в `artifacts/open/dev` — проверочный. В каждом наборе находятся 10 каталогов эпизодов и файл `episodes.json` с версиями, начальными значениями генератора и настройками.

| Файл | Содержание и назначение |
| --- | --- |
| `manifest.json` | Описание эпизода — компания, базовая валюта, период, часовой пояс, число записей и правила округления. |
| `policy.json` | Правила выбора валютного курса, учёта периода, расчёта сумм и оформления доказательств. |
| `ledger.csv` | Бухгалтерские проводки с суммами дебета и кредита, датами и ссылками на счета и платежи. |
| `invoices.jsonl` | Документы счетов поставщиков с суммами, датами, валютами и позициями. |
| `payments.jsonl` | Документы платежей и возвратов с распределением сумм по счетам. |
| `fx.csv` | Валютные курсы по датам с идентификаторами для ссылки в доказательствах. |
| `artifacts/evaluator/{train,dev}/<episode_id>/truth.json` | Закрытый эталон — ошибки, затронутые объекты, суммы и допустимые наборы доказательств. Доступен оценщику. |
| `artifacts/evaluator/{train,dev}/<episode_id>/provenance.json` | Закрытая история обратимых изменений и контрольная сумма исходных корректных книг. |
| `artifacts/trajectories.jsonl` | Действия, наблюдения, награды и признаки завершения 20 обучающих прогонов. |
| `artifacts/baseline_results.json` | Метрики, награды, число шагов и время 80 запусков четырёх базовых политик на 20 эпизодах. |
| `artifacts/.generated-by-fin-audit-rl` | Служебная отметка каталога, созданного генератором, для повторного обновления материалов. |

Технические имена файлов, команд и полей JSON используются в программном интерфейсе. Русские пояснения к типам ошибок приведены ниже.

| Значение `type` | Тип ошибки |
| --- | --- |
| `duplicate_invoice` | Дублирование счёта поставщика и его проводок. |
| `payment_allocation` | Пропущенное или неполное распределение платежа. |
| `fx_date_rate` | Неверный валютный курс или использование курса другой даты. |
| `period_cutoff` | Отнесение операции к неверному отчётному периоду. |

## Ограничения

Синтетическая модель охватывает ограниченные правила учёта и фиксированные договорные условия конвертации. Результаты характеризуют работу политик в этой среде. Улучшение модели при дообучении требует отдельного контролируемого сравнения на отложенных данных.
